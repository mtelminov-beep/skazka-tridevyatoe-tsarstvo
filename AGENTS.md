# Правила работы агентов над проектом «Тридевятое царство»

Над этим репозиторием параллельно работают несколько агентов — **Claude Code, Codex, Cursor** —
и живой человек. Этот файл читают все. Он про то, как не мешать друг другу.

Файл каноничный. Сокращённые копии и скиллы агентов должны совпадать с ним:

- `CLAUDE.md` и `.claude/skills/version-log/` — Claude Code
- `.codex/skills/version-log/` — Codex
- `.cursor/rules/` и `.cursor/skills/version-log/` — Cursor

Если правила меняются — правьте здесь и синхронизируйте остальные.

---

## Главное правило: три шага

Агенты работают **на разных компьютерах, в том числе одновременно**. Единственная общая
копия проекта — репозиторий на GitHub. Локальная папка на любой машине — временная копия,
и работа считается сделанной только после того, как она уехала на GitHub.

**1. Перед началом каждой новой задачи, которая может изменить файлы:**

```bash
node scripts/version.mjs sync
```

**2. После каждого завершённого изменения:**

```bash
node scripts/version.mjs bump --agent <claude|codex|cursor|имя> --type <patch|minor|major> -m "что сделано"
```

**3. Перед тем как закончить сессию:**

```bash
node scripts/version.mjs status
```

`status` показывает машину, ветку и всё, что не уехало: незакоммиченные правки,
неотправленные коммиты и теги, неподтянутые чужие версии. Ненулевой код возврата —
запрет заканчивать: сначала заверсионируйте и отправьте, потом отчитывайтесь человеку.

Всё остальное в этом файле — подробности этих трёх команд.

### Формат записи версии — обязателен для каждого изменения

Каждое завершённое изменение получает **свою** версию в формате
**номер · дата и время · агент · что сделано** (машина пишется автоматически):

```
v1.2.0 — 25.08.2026 14:31:07   [claude@DESKTOP-D0H2DER]   Добавлена игра «Доскажи словечко»
```

Ни одно изменение не остаётся без версии: правка без `bump` невидима для агентов
на других машинах и рано или поздно будет затёрта.

### Порядок обязателен: сначала локально, потом GitHub

Версия пишется в локальные файлы (`VERSION`, `.versions/*`, `CHANGELOG.md`), коммитится
с тегом и только после этого уходит на GitHub. Всё это делает один `bump` — руками
пушить журнал не нужно и нельзя. Обратный порядок (сначала push, потом запись версии)
невозможен: коммит с кодом и запись журнала — один коммит, иначе на другой машине
появится код без версии.

### Автоматика: правило не держится на памяти агента

У Claude Code три шага прошиты хуками в `.claude/settings.json`, чтобы правило
исполнялось, даже если агент про него забыл:

| Событие | Что запускается | Что даёт |
|---------|-----------------|----------|
| Начало сессии | `node scripts/version.mjs hook session-start` | Тянет чужие версии, показывает новые и чужие незакоммиченные правки |
| Конец каждого ответа | `node scripts/version.mjs hook stop` | Молчит, пока всё отправлено; иначе напоминает заверсионировать и запушить |

Команда `hook` — та же `sync` и `status`, только ответ в JSON. Сессию она не роняет:
при любой ошибке (нет сети, конфликт) хук возвращает нулевой код и пишет причину
в контекст. Проверить руками: `node scripts/version.mjs hook stop`.

У Codex и Cursor такого механизма нет — там три шага выполняются вручную по этому
файлу и по скиллу `version-log`. Правило одно для всех, различается только принуждение.

## Зачем sync перед работой

`sync` выполняет `git pull --rebase --autostash` и печатает версии, появившиеся с момента
вашей прошлой работы. Без него вы начнёте править устаревшую копию, а `bump` в конце
упрётся в конфликт слияния.

Посмотреть контекст:

```bash
node scripts/version.mjs current           # где сейчас проект
node scripts/version.mjs log --limit 10    # последние 10 версий
node scripts/version.mjs log --agent codex # что делал конкретный агент
node scripts/version.mjs status            # всё ли уехало на GitHub
```

## Несколько компьютеров: обязательные правила

Один и тот же агент (например, `claude`) запускается на разных машинах. Поэтому в каждой
записи журнала кроме агента хранится имя компьютера — видно, где сделана правка и чья
копия отстала. Имя берётся автоматически (`hostname`), переопределяется переменной
окружения `AGENT_HOST`, если у машин непонятные имена:

```bash
AGENT_HOST=library-kiosk node scripts/version.mjs bump --agent claude -m "…"
```

Правила, которые нельзя нарушать:

1. **GitHub — источник правды.** Проект переносится между машинами только через
   `git clone` / `git pull`. Копировать папку флешкой, архивом или через облачный диск
   нельзя: у копии своя история, слить её потом невозможно.
2. **Начинать работу только после `sync`.** Правка на устаревшей копии — главный
   источник конфликтов при параллельной работе.
3. **Заканчивать работу только с чистым `status`.** Незапушенный коммит на выключенном
   компьютере равен потерянной работе: остальные машины его не видят и правят то же место.
4. **Одно завершённое изменение — один `bump`.** Не копите правки на полдня и не сливайте
   несколько разных задач в одну версию: чем крупнее шаг, тем больнее конфликт и тем
   бесполезнее журнал.
5. **Если `bump` не смог отправить** (нет сети, отклонён пуш) — скрипт сообщит об этом
   и вернёт ненулевой код. Молча продолжать нельзя: либо повторите
   `git pull --rebase && git push && git push --tags`, либо прямо скажите человеку,
   что версия осталась только на этой машине.
6. **`--no-push` — только при отсутствии сети** и с обязательной пометкой в отчёте
   человеку. При первой же связи версию нужно дослать.
7. **История не переписывается.** Никаких `git push --force`, `git commit --amend`
   и rebase уже опубликованных коммитов: на других машинах это ломает копии.
8. **Ветка одна — `main`.** Она же собирается на панели. Если нужна отдельная ветка,
   это отдельная договорённость с человеком, а не решение агента.
9. **Локальное состояние не синхронизируется.** `backend/data/cms-state.json`,
   `media/uploads/*`, `node_modules/`, `dist/` живут на каждой машине свои, в git их нет.
   После `sync` на новой машине выполните `npm run install:all` и сборку.
10. **Долгая сессия — повторный `sync`.** Если между началом работы и `bump` прошло
    больше получаса, синхронизируйтесь ещё раз перед правкой: за это время другая
    машина могла тронуть те же файлы. Сам `bump` тоже делает `pull --rebase`, но
    разбирать конфликт лучше до, а не после написания кода.

## Незаверсионированные правки из Chrome

Человек может править проект через ChatGPT-надстройку в Chrome, особенно картинки,
тексты и медиа. Надстройка не всегда передаёт агентам сведения о таких правках и не
всегда делает `bump`, поэтому **перед каждой новой задачей, которая может изменить
файлы**, после `sync` обязательно проверьте рабочее дерево — даже если проверка уже
была в этой сессии:

```bash
git status --short
```

Если есть изменения, которых вы не делали, сначала изучите их (`git diff`, список новых
файлов), не затирайте и не форматируйте их. Если правки выглядят завершёнными и проект
собирается, оформите их отдельной версией до начала своей работы:

```bash
npm --prefix frontend run build
node scripts/version.mjs bump --agent chrome --type <patch|minor|major> -m "что изменено через Chrome"
```

Если правки явно незавершённые или сборка падает, не переписывайте их молча: сообщите
человеку, что Chrome оставил незавершённое состояние, и продолжайте только после
разрешения конфликта.

## Что делает bump

Одна команда закрывает весь цикл, локально и на GitHub одновременно:

1. `git pull --rebase` — забирает чужие версии;
2. считает следующий номер как **максимум из `VERSION`, журнала и git-тегов** — номер никогда не откатывается назад;
3. пишет `VERSION`, `.versions/current.json`, `.versions/log.jsonl`, `CHANGELOG.md` —
   номер, дату и время, агента, машину и описание;
4. коммитит и ставит аннотированный тег `vX.Y.Z`;
5. пушит ветку и тег. Если чужой пуш опередил — сам делает `pull --rebase`
   и повторяет попытку один раз.

Не редактируйте `VERSION`, `.versions/*` и `CHANGELOG.md` руками и не проставляйте номера
самостоятельно — это единственный источник расхождений между агентами.

### Выбор типа версии

| Тип | Когда | Пример |
|-----|-------|--------|
| `patch` | Багфикс, текст, стиль | Починена модалка, исправлена опечатка в сказке |
| `minor` | Новая возможность | Добавлен раздел, игра, поле в CMS |
| `major` | Ломающее изменение | Изменена структура каталогов CMS, переписан API |

### Описание изменения

По-русски, одной фразой, о сути а не о процессе.
Хорошо: `"Модалки вынесены в портал — окно больше не уезжает вниз"`.
Плохо: `"правки"`, `"обновление"`.

### Флаги на крайний случай

`--no-push` (нет сети) · `--no-commit` (только журнал) · `--no-pull` (не тянуть перед bump, рискованно)

## Как устроена защита от гонок

- **Append-only журнал.** `.versions/log.jsonl` только дописывается в конец. В `.gitattributes`
  для него и для `CHANGELOG.md` включён `merge=union` — параллельные записи сливаются сами.
  `VERSION` под union не заводим намеренно: это одна строка, и склеенные две сломали бы
  разбор. Номер всё равно считается как максимум из трёх источников, поэтому конфликт
  в `VERSION` разрешается любой из версий — следующий `bump` возьмёт число выше.
- **Файловая блокировка.** `.versions/.lock` не даёт двум агентам на одной машине писать
  одновременно. Зависшую дольше 2 минут блокировку скрипт снимает сам. Между машинами
  блокировка не работает — там от гонки защищают `pull --rebase` перед записью номера
  и повтор пуша после чужого коммита.
- **Номер из трёх источников.** Даже если журнал разъехался, следующий номер считается
  как максимум из `VERSION`, журнала и тегов — коллизия не приведёт к перезаписи чужой версии.
- **Секунды в отметке времени.** Два агента вполне успевают записаться в одну минуту,
  поэтому время пишется с точностью до секунды, а UTC-отметка хранится в ISO-формате.

Если два агента всё же взяли один номер, оставьте обе записи: они честно отражают
параллельную работу. Следующий `bump` возьмёт число выше.

## Как делить работу между агентами

Конфликтов не будет, если агенты берут **разные каталоги**. Ориентир:

| Зона | Что там | Кто обычно трогает |
|------|---------|--------------------|
| `frontend/src/data/` | Контент: сказки, герои, викторина, игры | Правки текстов — независимы, конфликтуют редко |
| `frontend/src/pages/` | Страницы разделов | Один агент — один раздел за раз |
| `frontend/src/components/` | Общая оболочка, фон, модалки | **Общая зона.** Предупреждайте в описании версии |
| `frontend/src/styles/` | Дизайн-система | **Общая зона.** Правьте точечно, не переписывайте файл целиком |
| `backend/src/` | API и CMS | Меняется редко, согласуйте изменение контракта |
| `AGENTS.md`, скиллы агентов | Правила | Меняются вместе, одним коммитом |

Правила простые:

1. **Не переформатируйте чужие файлы.** Массовый reformat превращает любое слияние в конфликт.
2. **Один смысловой шаг — один bump.** Не копите правки на полдня: чем крупнее коммит,
   тем больнее конфликт.
3. **Общие файлы — короткими правками.** В `components.css` и `types.ts` добавляйте
   в конец своей секции, а не перетасовывайте существующее.
4. **Если правите контракт** (`types.ts`, `catalogKeys.js`) — это `minor` или `major`,
   и скажите об этом прямо в `-m`: другие агенты увидят это в `sync`.

### Запуск

```bash
npm run install:all   # один раз
npm run dev:api       # бэкенд на 8803
npm run dev:web       # фронтенд на 5275
```

Порты переопределяются переменными окружения `API_PORT` и `WEB_PORT` — если 5275 или 8803
заняты соседним проектом, поднимите панель на других:

```bash
API_PORT=8812 npm run dev:api
API_PORT=8812 WEB_PORT=5284 npm run dev:web
```

Админка CMS: `http://127.0.0.1:5275/admin` (логин `admin`, пароль `admin`).

### Перед bump убедитесь, что проект собирается

```bash
npm --prefix frontend run build
```

`tsc` работает в strict-режиме, `noUnusedLocals` включён. Не коммитьте код, который не проходит сборку.

## Договорённости по коду

- Комментарии и весь текст интерфейса — **по-русски**.
- Комментарий объясняет **почему**, а не пересказывает код.
- Контент разделов живёт только в `frontend/src/data/` и правится через CMS —
  не хардкодьте тексты в компонентах.
- Любой новый раздел контента: тип в `types.ts` → данные в `data/` → ключ в
  `data/defaults.ts` **и** в `backend/src/catalogKeys.js`. Универсальный редактор
  админки подхватит его сам, отдельный редактор писать не нужно.
- Сведения о сказках — только проверяемые. Народная сказка живёт в десятках
  вариантов: выбрать один в пересказе можно, выдавать его за единственный — нет.
  Сверяйте по открытым источникам из раздела «Галерея» (собрание Афанасьева,
  Викитека, Викисклад, «Культура.РФ»).
- Тексты сказок целиком в код не пишем: сказку на панели слушают, а не читают
  с экрана. Поле `text` — короткий пересказ-опора, аудио библиотека грузит через админку.
- `position: fixed` внутри страниц не работает как ожидается: у `.page-enter` есть
  анимация с `transform`, у `.glass` — `backdrop-filter`, оба создают containing block.
  Всё оверлейное (модалки, конфетти) рендерите через `createPortal` в `document.body`.
- В CSS-гриде `::before` — такой же элемент сетки, как и дети. Два столбца плюс два
  ребёнка плюс псевдоэлемент = третий элемент уезжает на новую строку.

## Чего не делать

- Не коммитить `backend/data/cms-state.json`, `media/uploads/*`, `node_modules/`, `dist/` — они в `.gitignore`.
- Не задавать `CMS_ADMIN_PASSWORD` и `CMS_TOKEN` в коде. Только переменные окружения.
- Не переименовывать маршрут `/gallery` в `/media` — путь `/media` занят раздачей файлов,
  и страница перестанет открываться при перезагрузке.
- Не задавать `.media-fallback` собственный кегль: заглушка наследует размер контейнера,
  иначе эмодзи вылезает из кружка героя.
