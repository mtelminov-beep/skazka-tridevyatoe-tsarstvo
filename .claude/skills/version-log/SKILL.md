# Журнал версий проекта «Тридевятое царство»

Над репозиторием параллельно работают несколько агентов — Claude Code, Codex, Cursor —
и живой человек. Этот скилл держит их в общей картине: кто, когда и что изменил.

Всё делается одним скриптом `scripts/version.mjs`. Своих файлов версий не создавай,
номера руками не проставляй — иначе история разъедется.

Канон правил — [AGENTS.md](../../../AGENTS.md).

## Перед началом работы — всегда

```bash
node scripts/version.mjs sync
```

Подтягивает версии других агентов с GitHub (`git pull --rebase --autostash`) и печатает,
что появилось нового. **Не начинай править код, не выполнив sync** — иначе будешь работать
на устаревшей базе и создашь конфликт слияния.

Агенты работают с разных компьютеров, поэтому общая копия проекта только одна —
репозиторий на GitHub. Локальная папка на этой машине временная: правка считается
сделанной, когда она уехала на GitHub, а не когда сохранён файл.

Посмотреть, где остановились:

```bash
node scripts/version.mjs current
node scripts/version.mjs log --limit 10
```

`log` принимает `--agent codex`, чтобы увидеть правки конкретного агента.

## Незаверсионированные правки из Chrome

После `sync` и до своих изменений всегда проверь:

```bash
git status --short
```

Человек может менять проект через ChatGPT-надстройку в Chrome, особенно картинки и
медиа. Такие правки могут остаться без `bump`. Если видишь изменения, которых не делал,
сначала изучи `git diff` и новые файлы, не затирай их и не форматируй рядом. Если правки
завершены и сборка проходит, запиши их отдельной версией до своей работы:

```bash
npm --prefix frontend run build
node scripts/version.mjs bump --agent chrome --type <patch|minor|major> -m "что изменено через Chrome"
```

Если правки незавершённые или сборка падает, остановись и сообщи человеку, что Chrome
оставил рабочее дерево в состоянии, которое нужно разобрать.

## Несколько компьютеров

Один и тот же агент запускается на разных машинах, поэтому в каждой записи журнала
рядом с агентом хранится имя компьютера — видно, где сделана правка и чья копия отстала.
Имя берётся автоматически, при необходимости переопределяется `AGENT_HOST`.

- Проект переносится между машинами только через `git clone` / `git pull`.
  Копировать папку архивом или облачным диском нельзя — у копии своя история.
- Одно завершённое изменение — один `bump`. Не копи правки на полдня.
- Ветка одна — `main`. Отдельная ветка — только по договорённости с человеком.
- `git push --force`, `git commit --amend` и rebase уже опубликованных коммитов
  запрещены: на других машинах это ломает копии.
- `backend/data/cms-state.json`, `media/uploads/*`, `node_modules/`, `dist/`
  не синхронизируются — на новой машине выполни `npm run install:all` и сборку.
- Если между `sync` и `bump` прошло больше получаса, синхронизируйся ещё раз:
  другая машина могла тронуть те же файлы.

## После завершения изменения — всегда

```bash
node scripts/version.mjs bump --agent claude --type patch -m "Что именно сделано"
```

Одна команда делает всё сразу:

1. `git pull --rebase` — забирает чужие версии;
2. вычисляет следующий номер (максимум из `VERSION`, журнала и git-тегов — номер не откатится);
3. пишет `VERSION`, `.versions/current.json`, `.versions/log.jsonl`, `CHANGELOG.md`;
4. коммитит, ставит аннотированный тег `vX.Y.Z`;
5. пушит ветку и тег на GitHub. Если чужой пуш опередил, скрипт сам делает
   `pull --rebase` и повторяет попытку один раз.

Локальная копия и GitHub обновляются в одном шаге — расхождения не возникает.
Если отправить не удалось (нет сети, конфликт), скрипт скажет об этом и вернёт
ненулевой код. Молча продолжать нельзя: повтори `git pull --rebase && git push &&
git push --tags` или сообщи человеку, что версия осталась только на этой машине.

Запись выглядит так: `v1.2.0 — 25.08.2026 14:31:07  [claude@имя-машины]  Добавлена игра «Доскажи словечко»`.

### Как выбрать `--type`

| Тип | Когда | Пример |
|-----|-------|--------|
| `patch` | Правка бага, текста, стиля | Починил модалку, поправил опечатку в сказке |
| `minor` | Новая возможность без слома старой | Добавил раздел, новую игру, поле в CMS |
| `major` | Ломающее изменение | Сменилась структура каталогов CMS, переписан API |

### Как писать `-m`

По-русски, по существу, одна фраза о сути — не о процессе.

- Хорошо: `"Модалки вынесены в портал — окно больше не уезжает вниз"`
- Плохо: `"правки"`, `"фиксы"`, `"обновление кода"`

### Обязательно укажи себя в `--agent`

`claude`, `codex`, `cursor` или имя человека. По этому полю разбирают, кто что менял.
Можно один раз задать переменную окружения `AGENT_NAME`, тогда флаг не нужен.

## Перед тем как закончить сессию — всегда

```bash
node scripts/version.mjs status
```

Показывает машину, ветку и всё, что не уехало: незакоммиченные правки, неотправленные
коммиты и теги, неподтянутые чужие версии. Ненулевой код возврата — запрет заканчивать:
сначала заверсионируй и отправь, потом отчитывайся человеку. Незапушенный коммит на
выключенном компьютере равен потерянной работе.

## Перед bump — проверь сборку

```bash
npm --prefix frontend run build
```

`tsc` в strict-режиме. Версию с неработающей сборкой ставить нельзя: её подтянут
остальные агенты.

## Флаги на крайний случай

- `--no-push` — записать версию, но не отправлять (нет сети). Обязательно скажи
  об этом человеку и дошли версию при первой связи: `git push && git push --tags`
- `--no-commit` — только обновить файлы журнала
- `--no-pull` — не тянуть с сервера перед bump (осторожно: риск дублирования номера)

## Если что-то пошло не так

**«Журнал занят другим агентом»** — параллельный агент прямо сейчас пишет версию.
Подождите 10–20 секунд и повторите. Если процесс упал и блокировка зависла дольше
двух минут, скрипт снимет её сам; можно удалить `.versions/.lock` вручную.

**Конфликт при pull** — `.versions/log.jsonl` и `CHANGELOG.md` настроены на `merge=union`
в `.gitattributes` и сливаются сами. Конфликт в них означает, что union-стратегия
не применилась: проверьте `git config merge.union.driver`. В остальных файлах разрешайте
конфликт обычным порядком, затем повторите `bump`.

**Два агента взяли один номер** — такого быть не должно (номер считается как максимум
из трёх источников после pull), но если случилось, `bump` следующего агента просто
возьмёт число выше. Дубликат в журнале можно оставить: он честно отражает, что работа шла
параллельно.

## Где что лежит

| Файл | Назначение |
|------|-----------|
| `VERSION` | Текущий номер, одна строка. Для машин |
| `.versions/current.json` | Номер + дата/время + агент + машина + сводка |
| `.versions/log.jsonl` | Append-only журнал, одна запись в строке |
| `CHANGELOG.md` | Человекочитаемая история, новое сверху |
| git-теги `vX.Y.Z` | Снимок кода на момент версии |

Вернуться к состоянию любой версии: `git checkout v1.2.0`.
